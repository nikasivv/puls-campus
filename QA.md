## Важнейшие сценарии ручной приёмки

- [ ] Сотрудник меняет аудиторию **на одну дату**, студент получает уведомление и открывает точный день; последующая неделя не изменяется.
- [ ] При переходе на чётную/нечётную недели появляются разные занятия, общие занятия видны в обеих.
- [ ] При редактировании общего занятия только для одной чётности вторая остаётся неизменной.
- [ ] Вкладки деканата разделены, смена фильтра группы не показывает другую группу по инерции.
- [ ] Временные интервалы задаются в «Сетке звонков», в карточке выбирается **номер пары**, время подставляется.
- [ ] При попытке занять тот же номер пары дважды на одной неделе выдаётся ошибка, конфликт не сохраняется.
- [ ] «Сделать недели одинаковыми» требует чекбокса, заменяет целевой шаблон, не стирает разовые переносы.
- [ ] Заявка не может стать «Готова» без выданного результата; студент скачивает PDF, у чужого аккаунта 404.
- [ ] Данные успеваемости разделены по семестрам; ранние ноябрьские «итоги» не попадают в архив ноября 2026.
- [ ] Уведомления находятся в колокольчике; есть счётчик, переход к дате и массовая отметка прочитанным.
- [ ] CSV с корректными группами: загрузка → предпросмотр → подтверждение → однократное получение приглашений → активация → вход; до подтверждения аккаунтов нет.
- [ ] CSV с дубликатами или неизвестными группами не создаёт ни одного аккаунта.
- [ ] Студент не может открыть административные или деканатские POST-маршруты; действует CSRF.
- [ ] 360/390/768/1280 px, в том числе раскрытые карточки, формы ошибок и popup уведомлений.
- [ ] Развёрнутый URL открывается из РФ без VPN, SQLite сохраняет данные при перезапуске, секреты настроены.

## Безопасность и границы

Это конкурсный прототип на **вымышленных** данных. Публичный быстрый вход, возможность сотрудника просматривать всех демостудентов, отсутствующие корпоративные SSO/ограничение полномочий по подразделениям не соответствуют полноценному реальному вузу. Не публикуйте CSV с настоящими студентами и не храните CSV с токенами приглашений в открытом репозитории. В этой версии внешняя интеграция с вузовским реестром намеренно отсутствует.

## Добавление v6 · данные занятия и детализация

- **PASS (локальные тесты):** 15 независимых тестов `test_calendar_pure.py` и `test_session_metadata.py`, включая несколько групп/преподавателей/аудиторий, точечную замену и отмену для одной группы.
- **PASS (проверка реальных SQLite-запросов без Flask):** маршрутные функции создания, редактирования, разовой замены и удаления общей пары; конфликт второй пары в том же слоте блокируется, при смене чётности прежняя неделя сохраняется. Это не заменяет HTTP-тестов Flask.
- **PASS (миграция):** схема v5 обновлена до v6 без изменения 4 аккаунтов, 10 оценок, 1 обращения и 24 записей регулярного расписания.
- **PASS (идемпотентность):** новая демонстрационная SQLite дважды проходит `init_db()` без повторного создания аккаунтов и трёх групп общей лекции.
- **PASS (статические рендеры/Chromium):** открытие и закрытие подробностей на ширине 360 и 1280 px; правильные дата, время, тип, три группы, две аудитории и два преподавателя; нет горизонтального переполнения страницы. Источник — статически срендеренный HTML с реальным CSS и JS проекта, а не запущенный Flask-сервер.
- **ОГРАНИЧЕНИЕ:** полноценные HTTP-интеграционные тесты Flask на сервере по-прежнему не проведены: зависимости Flask не удалось скачать в изолированной среде (DNS недоступен). После установки зависимостей необходимо выполнить `python -m unittest discover -s tests -v`, проверить реальные формы в браузере и развернуть доступную из РФ ссылку.

Ручные проверки дополнительно: создать общую лекцию для двух групп; войти под каждым студентом при условии его привязки к группе; изменить аудиторию сразу у двух групп; сделать разовый перенос только у одной и проверить, что у другой прежнее занятие осталось; отменить общую лекцию и убедиться в уведомлениях.
