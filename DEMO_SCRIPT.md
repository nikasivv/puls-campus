# ПУЛЬС v5 · Демонстрация для жюри (до 5 минут)

## Сценарий одной связанной системы

**0:00–0:30 · Проблема и концепт.** В большинстве кабинетов студент читает статусы, но всё равно идёт в деканат. В ПУЛЬС важен не статус, а доведение задачи до результата. У нас три роли и принцип «одно действие — понятный следующий шаг».

**0:30–1:10 · Календарь студента.** Войти в `student1` одной кнопкой. В расписании открыть 23 ноября 2026 (чётная неделя), выбрать предшествующую нечётную неделю, раскрыть карточку пары: преподаватель, аудитория и конкретные часы. Никаких декоративных ссылок. Открыть «Успеваемость»: текущий осенний семестр отдельно от завершённой весны; итогов будущих экзаменов нет.

**1:10–2:00 · Настройка звонков и недели деканатом.** Войти в `dean` → вкладка «Расписание» → выбрать группу БИ-24-1 → показать сетку звонков → раскрыть ячейку «4 пара» и добавить учебный предмет для нечётной недели, при желании выбрать «обе недели». Переключить чётную. Продемонстрировать синхронизацию: можно сделать шаблон одной недели общим для обеих.

**2:00–2:35 · Разовое изменение.** Деканат → «Один день, без изменения шаблона»: выбрать 25 ноября, сменить аудиторию существующей пары (или отменить занятие), сохранить причину. Вернуться в student1 → колокольчик с новым событием → открыть конкретную дату. Следующая среда остаётся по обычному шаблону.

**2:35–3:25 · Реальная справка.** Студент создаёт «Справка об обучении», деканат берёт её в работу, при необходимости запрашивает уточнение; студент отвечает. Деканат завершает с автоматической PDF-справкой. Студент видит «Твой ход»/«Результат готов», получает PDF. Другой студент не может скачать документ по чужой ссылке.

**3:25–4:15 · Зачисление в вуз.** Войти в `admin`, показать `enrollment_example.csv`. Администратор загружает подтверждённый **вымышленный** список; предпросмотр подсвечивает дубликаты, неизвестные группы и ошибки. Подтвердить импорт: скачивается CSV со ссылками активации. Открыть одну ссылку, установить пароль, войти новым студентом и получить расписание своей группы. Никакой саморегистрации без проверки зачисления.

**4:15–5:00 · Инженерная работа и критерии.** Показать архитектуру Python / HTML / CSS / SQLite, тесты календаря и миграцию старой базы, мобильную ширину 360 px. Отдельно сказать: «Прототип не подключён к системам вуза, данные вымышлены, быстрый вход — только для жюри». При публикации проверить ссылку без VPN из России.

### До записи видео

- [ ] Запустить `python -m unittest discover -s tests -v`, исправить все ошибки.
- [ ] Проверить реальный Flask-сервер, 360 px, календарь, CSV, выдачу PDF и четыре демоаккаунта.
- [ ] Убедиться, что публичный сервер доступен из РФ, данные сохраняются между перезапусками, ссылка живая.
- [ ] Видео записывать **только с вымышленными данными**, приглашения с реальными токенами не публиковать.

### Дополнительный сценарий v6 — общая лекция (30–45 секунд)

1. Студент `student1` → «Расписание» → дата ближайшего понедельника, на котором есть лекция «Системы искусственного интеллекта и большие данные».
2. Показать на карточке синие метки `ЛК`, «1 пара», 09:00–10:30, две аудитории и двух преподавателей. Нажать карточку: в панели видны **три группы, дата, тип, преподаватели и аудитории**.
3. Переключиться в деканат → «Расписание» → `БИ-24-1` → раскрыть ту же пару. Показать поля «Тип занятия», «Преподаватели», «Аудитории» и выбор сразу нескольких групп. Доказательство работы: изменить аудиторию для выбранных групп; вернуться в аккаунт студента, убедиться, что карточка обновилась.
4. По желанию показать точечную замену одной даты только для одной группы: другие группы продолжают видеть свою пару. После демонстрации восстановить прежнее расписание.
